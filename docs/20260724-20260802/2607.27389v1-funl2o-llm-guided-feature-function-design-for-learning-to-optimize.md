## 摘要
学习优化（L2O）方法通过训练模型来预测解、热启动、分支决策或其他形式的求解器指导，从而加速重复优化过程。这些流程中一个关键但常被忽视的组件是特征函数，它将问题实例映射为机器学习模型的输入。现有的L2O方法通常依赖手工设计的特征，使得表示设计成为手动过程，且在不同领域间基本固定。我们引入了FunL2O，这是第一个通过LLM驱动的程序演化来自动化L2O特征设计的统一框架。在类FunSearch的循环中，LLM提出可执行的特征函数，而固定的评估过程则重新训练原始L2O模型并衡量下游优化性能。我们在涉及解预测和热启动的线性与二次规划任务，以及使用GNN引导的后门分支和预测-搜索的混合整数优化任务上评估了FunL2O。在连续和离散优化任务以及四种LLM上，演化出的特征始终优于手工设计的表示。这些结果确立了LLM驱动的特征演化作为自动化L2O表示设计的一种通用且有效的方法。

## Abstract
Learning-to-optimize (L2O) methods accelerate repeated optimization by training models to predict solutions, warm starts, branching decisions, or other forms of solver guidance. A critical yet largely overlooked component of these pipelines is the feature function that maps problem instances to inputs for machine learning models. Existing L2O methods typically rely on hand-crafted features, making representation design manual and largely fixed across domains. We introduce FunL2O, the first unified framework for automating feature design through LLM-driven program evolution for L2O. In a FunSearch-style loop, an LLM proposes executable feature functions, while a fixed evaluation process retrains the original L2O model and measures downstream optimization performance. We evaluate FunL2O on linear and quadratic programming tasks involving solution prediction and warm-starting, as well as on mixed-integer optimization tasks using GNN-guided backdoor branching and Predict-and-Search. Across continuous and discrete optimization tasks and four LLMs, the evolved features consistently outperform hand-crafted representations. These results establish LLM-driven feature evolution as a general and effective approach to automating representation design in L2O.

## 1. 核心问题与整体含义

- **研究动机**：学习优化（L2O，Learning-to-Optimize）方法通过训练神经网络来加速重复性优化问题的求解，其应用涵盖解预测、热启动、单纯形基选择、分支决策等。然而，所有 L2O 流程都有一个共同的基础设计决策——**特征函数**（feature function），即将优化实例映射为机器学习模型输入的程序。
- **核心问题**：现有 L2O 方法的特征函数几乎全部依赖**手工设计**，且在不同问题领域间基本固定不变。特征函数决定了模型能直接获取哪些信息——当有用的关系未被显式编码时，模型只能从原始输入中隐式推断。因此，仅改变输入表示就可能显著影响模型表达能力和下游优化性能。
- **整体含义**：特征函数设计应当被视为 L2O 流程中一个**独立且可自动化的组件**，而非一个固定前提。论文通过 LLM 驱动的程序演化，将特征设计从"人工经验"转变为"数据驱动的搜索过程"。

## 2. 方法论

### 核心思想
FunL2O 采用 **FunSearch 风格的进化循环**：LLM 生成可执行的特征函数候选，经过语义合约验证后，替换原 L2O 流水线中的手工特征，重训练模型并测量下游优化性能，以实测结果（而非 LLM 主观判断）指导下一轮搜索。

### 关键技术细节

- **流程表述**：一个 L2O 流水线可表示为 \( x \xrightarrow{\phi} X \xrightarrow{M} a \xrightarrow{S} y \)，其中 \(\phi\) 为特征函数，\(M\) 为学习模型，\(S\) 为下游求解器。FunL2O 仅替换 \(\phi\)，其余全部固定。
- **特征设计问题形式化**：\(\phi^\* \in \arg\min_{\phi \in \Phi_P} \rho_P(\phi)\)，其中排名键 \(\rho_P = (b_P, v_P, q_P)\) 按字典序排序（可行性条件 → 不可行程度 → 目标质量或求解工作量），防止不可行解因目标更优而被误选。
- **语义特征合约** \(C_P = (U_P, Z_P, I_P, V_P)\)：定义可用输入字段、输出格式与最大特征宽度、必须满足的不变量，以及可执行验证器。合约支持异构图、密集张量和求解器状态等不同接口，使同一搜索流程适用于不同 L2O 方法。
- **种子保留机制**：候选通常采用追加式结构 \(\phi(x) = \text{Concat}(\phi_0(x), \psi(x))\)，保留手工特征通道。手工特征作为基线留在搜索记忆中，若无可改进候选则被选中，确保"最差也不劣于基线"。
- **搜索流程**：初始评估手工特征 → 每代基于精英记忆构造提示词 → LLM 提出 6 个候选 → 静态+动态验证（最多修复 3 次）→ 并行重训练评估 → 按排名键更新记忆 → 选择 Top-2 精英进入下一代。共 8 代、48 个候选。
- **评估标准**：每个候选必须完整重训练原 L2O 模型，使用原始数据、损失、优化器和调度，在验证集上按管线原生指标（目标间隙、可行性、迭代节省、枢轴数、墙钟时间等）排序。测试集结果仅用于最终报告，不参与搜索。

## 6. 主要结论与发现

- **演化特征普遍优于手工特征**：
  - IPM-MPNN 上所有 5 个 LP 分布目标间隙降低 16.4%–49.4%；
  - FSNet 上非凸 SOCP 间隙从 933.85% 降至 141.28%，可行性从 0.25 提升到 1.00；
  - PDHG-Net 迭代节省从 42.44% 提升至 51.05%，时间节省从 34.03% 提升至 39.28%；
  - Learning to Pivot 枢轴数几何均值降低 26.2%（1162.86 → 857.78）；
  - MILP 中后门分支墙钟时间相对默认求解器缩短 11.7%–55.2%，胜率最高达 49%。
- **特征宽度增加不是性能提升的主因**：匹配宽度条件下 FunL2O 仍优于随机特征（6 个受控设置中 5 个最优），说明搜索到的**语义结构**承载了主要增益。
- **进化反馈本身有独立贡献**：PDHG-Net 上同等 48 次 LLM 调用预算，无反馈独立采样为 44.42%，有反馈进化为 52.23%，7.81 个百分点可归因于反馈机制。
- **可解释性**：演化程序可直接检视，如集合覆盖中暴露"列覆盖度归一化目标成本"、PageRank 中暴露"行列质量不对称性"、SOCP 中构建"多尺度归一化变换"。
- **跨模型通用性**：Claude、GPT-5.5、Gemini 在 20 个共享单元中分别改进 15、17、17 个，不依赖单一 LLM 供应商。提案模型能力越强，生成有效特征越可靠。

## 7. 优点

- **统一解决范式**：首次将 L2O 的特征设计问题形式化为程序搜索问题，一个框架即可适用于解预测、热启动、枢轴选择、分支决策等异构流水线。
- **语义合约设计精巧**：以可执行验证器将 LLM 生成自由性与管线接口约束有效衔接，同时保障部署时信息可用性（禁止访问标签、求解器、文件等）。
- **评估隔离与公平性**：LLM 不做性能判断，所有选择基于重训练后的实测下游指标；搜索不接触测试集；3 种子配对比较消除了训练随机性干扰。
- **广泛而深入的对照**：匹配宽度、独立采样、种子保留、多种 LLM 等对照设计严谨，有效排除了"仅宽度增加"和"best-of-many"等替代解释。
- **可解释性与可用性俱佳**：选出的是普通预处理代码，可直接部署、无需 LLM，且可作为"原始表示缺了什么"的可解释假设。
- **保守性原则**：手工特征永远保留在搜索记忆中，保证最差结果不劣于基线，低风险即可获得增益。

## 8. 不足与局限

- **离线搜索成本较高**：每次搜索需约 25.3 小时计算加约 $192 LLM API 费用，候选评估依赖完整重训练，对于大规模模型或问题可能成为瓶颈。虽有并行化空间，但论文未在实际实验中报告并行加速效果。
- **对 LLM 能力有依赖**：DeepSeek-Math-V2 在 20 个共享单元中仅改进 6 个，显著弱于其他模型，说明框架效果受提案模型质量制约。较弱的 LLM 可能产生大量无效候选，浪费评估预算。
- **收益并非普适**：部分任务上演化特征与手工特征持平（如非凸 QP 的 FSNet gap 保持 5.46，非光滑 QP 保持 5.20），说明手工特征在某些情况下已接近局部最优，搜索空间内未必存在显著更优解。
- **潜在过拟合风险**：虽然使用验证集选择、测试集报告降低了过拟合，但搜索过程可能在验证分布上过拟合（尤其是分布内评估）。论文未测试跨分布泛化（如从集合覆盖迁移到其他组合问题）。
- **MILP 实验覆盖较窄**：仅用 2 种 LLM、3 个 MILP 域，且 40 个测试实例的规模相对较小，结论的统计力度弱于连续优化实验。
- **细节缺失**：GPU 具体型号与数量未报告；搜索的失败率、修复次数分布、候选有效通过率等过程性统计未披露；随机特征控制仅覆盖 6 个设置中的部分任务。
