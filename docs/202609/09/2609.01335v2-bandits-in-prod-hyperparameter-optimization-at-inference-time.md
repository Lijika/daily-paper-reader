## 摘要
许多生产系统只能通过在实际请求上使用配置并观察噪声反馈来评估配置。现代智能体系统是一个典型例子，在推理时存在模型选择、检索深度、提示策略和解码温度等选择，但通常没有代表性的验证数据。我们将此设置形式化为在线超参数优化（OHPO），并将其视为在混合和条件搜索空间上的无穷多臂老虎机问题。我们提出了IMABO，一个通用框架，它将任何用于在已采样配置中进行选择的bandit策略与任何用于提出新配置的oracle相结合。我们使用IMOSS对其进行实例化，IMOSS是一种无重启的任意时间策略，其活跃集以$t^\beta$的速度增长，并证明了期望累积分位数遗憾界为$O(p_\rho^{-1/\beta} + T^{(1+\beta)/2})$，其中$\beta\in(0,1)$控制活跃集增长，$p_\rho$下界了提议配置落入搜索空间顶部$\rho$比例的概率。我们将IMOSS与三个实用的oracle结合：树结构Parzen估计器、由逐坐标bandit驱动的现有解变异oracle，以及预训练表格基础模型，这三个oracle均优于均匀随机oracle基线。在从调整经典机器学习模型到配置基于LLM的智能体的各种OHPO设置中，IMABO在遗憾方面优于所有基线。我们的实现可在https://github.com/Tiime-Software/IMABO获取。

## Abstract
Many production systems can assess a configuration only by using it on live requests and observing noisy feedback. Modern agentic systems are a prominent example, with inference-time choices such as model selection, retrieval depth, prompting strategy, and decoding temperature, yet often with no representative validation data. We formalize this setting as Online Hyperparameter Optimization (OHPO) and cast it as an infinitely many-armed bandit over mixed and conditional search spaces. We introduce IMABO, a general framework that combines any bandit policy for choosing among already sampled configurations with any oracle for proposing new ones. We instantiate it with IMOSS, a restart-free anytime policy whose active set grows as $t^β$, and prove an expected cumulative quantile-regret bound of $O(p_ρ^{-1/β} + T^{(1+β)/2})$, where $β\in(0,1)$ controls active-set growth and $p_ρ$ lower-bounds the probability that a proposed configuration falls in the top-$ρ$ fraction of the search space. We combine IMOSS with three practical oracles: a Tree-structured Parzen Estimator, an incumbent-mutation oracle driven by a per-coordinate bandit, and a pretrained tabular foundation model, all three improving over the uniform random oracle baseline. IMABO outperforms all baselines in terms of regret across diverse OHPO settings, from tuning classical machine-learning models to configuring LLM-based agents. Our implementation is available at https://github.com/Tiime-Software/IMABO.

## 1. 论文的核心问题与整体含义（研究动机与背景）

**核心问题**：传统的超参数优化（HPO）通常在离线状态下进行——先在固定验证集上评估配置并选出最优超参，然后部署。但现代生产系统，尤其是基于LLM的智能体系统，面临一种截然不同的情形：

- **没有代表真实使用场景的离线验证集**：LLM系统由外部供应商提供，系统只能暴露推理时的设置（如模型选择、温度、提示策略）。
- **评估只能在线上通过真实请求完成**：每一次评估都是一次服务请求，产生的是带噪声的实时反馈。
- **探索是有代价的**：由于持续在线服务，累积奖励才是关键，而非最终推荐的单项质量；且水平线（horizon）未知。

**问题本质**：论文将此形式化为**在线超参数优化（Online Hyperparameter Optimization, OHPO）**——每个配置对应一只臂，每次请求对应一次拉动，配置空间通常是混合了连续、整数与分类参数的**混合/条件搜索空间**，配置数远超可服务的请求数，这构成**无穷多臂老虎机（IMAB）**问题。已有方法要么假设连续度量结构（对分类参数无效），要么随机采样新配置（不利用历史奖励信息）。

**整体意义**：论文在HPO与MAB理论交汇处提出可落地的框架，为生产环境中的在线超参搜索提供了第一个同时具备**无重启、任意时间（anytime）、累积分位数遗憾界**的方法，对推理时配置LLM/RAG系统具有直接的工业价值。

## 2. 论文提出的方法论

### 2.1 核心思想

论文提出 **IMABO（Infinitely Many-Armed Bandit with Oracle）** 框架，核心是**将“在已探索配置中选择”与“提出新配置”解耦**：

- **活跃集（active set）**：维护已见过的有限配置集合 M_t。
- **Bandit策略 A**：负责在活跃集中选择臂（即分配下一次服务请求的配置），处理探索/利用平衡。
- **Oracle O**：负责在历史观察的基础上提议新配置，决定哪个新臂应被加入活跃集。
- 设置 baseline 分布 P0，将性能目标定义为对 top-ρ 分位数的**ρ-regret**（而非与不可达的全局最优比较）。

### 2.2 IMOSS 策略

IMOSS（Infinitely Many-armed Optimistic Search Strategy）是该框架下的默认 bandit 策略：

- **适应 MOSS 指数**：采用任意时间 MOSS（anytime MOSS）指数 B_t(x) = μ̂_x + sqrt( ½(1+α)·max(0, log(tK_t/n_x))/n_x )，用当前轮次 t 代替未知水平线 T，用当前活跃集大小 K_t 代替固定臂数 K。
- **幂律增长活跃集**：当 |M_t| < t^β（β∈(0,1)）时从 oracle 请求新臂。实验取 β=0.5，活跃集按 √t 增长。
- **预热**：开始前先抽 N_s=10 个配置各服务一次。
- **理论保证**：在满足“oracle每次提议落入 top-ρ 集合的条件概率至少 p_ρ”的假设下，证明期望累积 ρ-regret 界限为 **O(p_ρ^(-1/β) + T^((1+β)/2))**——发现子线性，利用项为 T^((1+β)/2)，来自 MOSS 分配遗憾的 √(K_T·T) = T^((1+β)/2)（因为 K_T = T^β）。

### 2.3 三种学习型 Oracle

| Oracle | 关键思想 | 特点 |
|---|---|---|
| **IMOSS-TPE** | 用 MOSS 指数对活跃集排序，按分数分群，Parzen 密度比 ℓ/g 选提议 | 全局提议；无度量依赖；天然支持离散/分类/条件空间 |
| **IMOSS-mutate-KL×PE** | 先在活跃集中取经验均值最高的臂 x̂（**注意：不是MOSS正在拉的臂**），再用 KL-UCB bandit 选要变异的坐标，最后用该坐标上的一维Parzen估计器生成新值 | 局部搜索；不建全局模型；单次调用成本极低 |
| **IMOSS-TabPFN** | 用已探索臂的配置—均值作为 in-context 表格，由 TabPFN-3 预测候选池的分布，按 0.975 分位数排名选臂；候选池 = 90个围绕x̂的局部变异 + 10个从P0随机抽取，并清理池中重复/已在活跃集中的候选 | 局部搜索+全局预训练代理；无需训练 |

三种学习型 oracle 均优于均匀随机（IMOSS-Random）基线。

## 3. 实验设计

### 3.1 层级 1：玩具函数
- **函数**：Sin1、Garland、Rastrigin（三者均为可分离函数），Gaussian（不可分离、双峰）。
- **噪声**：可分离函数为加性高斯噪声（σ=0.7）；Gaussian为 Bernoulli 单次观测。
- **对比基线**：StoSOO、HOO-T、StroquOOL（树结构乐观优化）与 Hier-MAB-11（因子化 bandit，AutoRAG-HP），预算 T∈{1000,3000,5000,10000}×20个随机种子。
- **两个子实验**：(a) 比较 IMOSS-TPE 与优化基线在“简单遗憾 vs 在线平均遗憾”联合表现；(b) 与 TPE-k（k∈{1,10,50,70,100,200}固定复制）对比，检查 IMOSS 自适应分配的价值。

### 3.2 层级 2：HPOBench
- **离散任务**：3个 OpenML 分类任务（segment、credit-g、numerai28.6）上的随机森林配置（K=2250 个离散臂），采用 Bernoulli 化在线奖励；30个配对运行×T=5000。
- **连续任务**：kr-vs-kp 数据集（任务 167149）上的 Logistic Regression（二维 log 空间）与 SVM（二维 log 空间），T∈{1000,3000,5000,10000}×20个种子，对比 StoSOO、StroquOOL、HOO-T 与 Hier-MAB-10。

### 3.3 层级 3：HotpotQA 上的 LLM RAG 问答系统
- **场景**：BEIR 检索版 HotpotQA，检索增强生成 pipeline。检索器选择 top_k 个维基段落，LLM 从包含段落和问题的 prompt 生成答案。
- **搜索空间**（混合）：top_k∈{1…10}、温度∈[0,1]、prompt模板∈{few_shot, zero_shot, naive}、模型∈{6个不同供应商的LLM}。
- **奖励**：0.8·答案F1 + 0.2·检索F1。
- **对比**：IMOSS-TPE、IMOSS-mutate-KL×PE、IMOSS-TabPFN vs Random 与 Hier-MAB；5个随机种子、5000个在线问题+500个脱离流验证集。

### 3.4 层级 4：延迟与审查反馈
- **场景**：YAHPO-Gym surrogate 上的 LCBench 三个实例（higgs、APSFailure、Fashion-MNIST），7维混合搜索空间。

## 6. 论文的主要结论与发现

1. **IMABO/IMOSS 在几乎所有任务上优于基线**：在玩具函数、HPOBench 离散、连续问题以及真实 LLM 系统上，IMOSS 系列在累积遗憾上均优于/持平最优基线，且无需预知水平线。
2. **IMABO 家族的关键优势在“在线平均遗憾”而非“简单遗憾”**：比如在 HotpotQA 上 Hier-MAB 的最终推荐质量与 IMOSS 相当，但在线累积遗憾显著更差——证明在线优化目标（累积奖励）与最终推荐质量（简单遗憾）是两个不同维度，IMOSS 更好地优化前者。
3. **局部变异 oracles > 全局 TPE**：在几乎全部真实任务（除 higgs 外）上，mutate-KL×PE 与 TabPFN（局部、围绕当前最优臂）的累积后悔均低于 TPE（全局提议）。深层原因并非局部 oracle 使 bandit 策略更善于选择，而是使活跃集中的其他臂在“偏离最优臂时更便宜”，即群体的密度分布整体靠近高性能区。
4. **TabPFN oracle 在“最优区稀疏、需多参数同时正确”的任务（higgs）上才体现代价值**——其提出最优臂的间隙显著小于其他 oracles。
5. **延迟感知的切换规则（延迟/审查反馈下）几乎恢复了与无延迟天上界的差距**，显著优于延迟盲的扩展策略；尽管约 81% 的反馈被丢弃，仍能打败看到即时反馈的 UCB-AIR。
6. **TPE-k 消融证明自适应评估分配的价值独立于已探索配置的数量**——即使 TPE-50/TPE-70 的代理模型使用了与 IMOSS-TPE 相同或更多的不同配置拟合，IMOSS-TPE 的累积后悔仍更低。

## 7. 优点

1. **问题定义好**：OHPO 的精确定义（ρ-regret、baseline 分布、活跃集扩张）填补了离线 HPO 与在线学习之间的空白，具有实践真实感（延迟/审查反馈的处理也直接面向生产）。
2. **模块化设计**：IMABO 将 bandit 策略与 arm 提议 oracles 解耦，可任意组合，为未来在 oracle 侧引入 LLM、上下文信息或约束打下开放接口——这个“框架”设计提供了高度可扩展性。
3. **理论+实践并重**：给出了 IMOSS 的累积分位数遗憾界（分析经得起推敲：先证带随机停止时间的 MOSS 分配引理，再对发现/扩张/利用三分段拼接）；同时注重实际工程问题（延迟反馈、空间增长后的重启）。
4. **乐观原则细粒度应用**：在 TPE 分配好/坏组时使用 MOSS 指数而非经验均值，在 TabPFN oracle 中用分位数代替均值+κ·σ 的启发式，这些细节体现理论意识。
5. **严格分解后悔来源**：附录 C 的后悔分解（最优臂间隙 vs 其他臂成本）与“臂变异将活跃集集中在最优区从而使政策偏离最优臂的成本变小”的解释互相呼应，实验解释链条完整着落。

## 8. 不足与局限

1. **算力/资源未披露**：无任何 GPU 或 API 调用的成本信息，可复现性、资源可扩展性评估都存在缺口。
2. **水平线不对称比较**：基线（StoSOO、StroquOOL、HOO-T）均被给出 T（预知水平线），而 IMOSS 不需要；反过来说明 IMOSS 在更劣势的信息条件下仍胜出，说明结果可信，但这毕竟不是完全对等下的比较。
3. **未与几种重要基线比较**：未与贝叶斯优化类 SOTA（如 BORE/BTT、基于信任区域的 mixed categorical BO）或前沿上下文 bandit（PFN-TS）在各自基准上对比——有些是并发工作（[27]），但这限制了业界对其相对地位的判断。
4. **HotpotQA 结论的种子数偏少**：5个种子的随机排列只能给出较粗的标准差估计，断言“两个变异 oracles 与 Hier-MAB 简单遗憾统计上不可区分”的检验力明显有限。
5. **理论假设考察较弱**：top-ρ 覆盖假设（p_ρ）在实验中未被量化评估；不同 oracles 实际达到的 p_ρ 水平是否满足或优于 ρ 未知，这限制了理论结果与实际观察之间的直接联系。
6. **延迟/审查实验为仿真研究**：延迟与审查完全由 surrogate 人为构造（feedback_freq=0.2、q=0.95 patience 等），真实生产环境中的反馈模式可能远比这些参数复杂，结论外推需谨慎。
7. **β 的选择凭经验**：论文只证明 β∈(0,1) 的理论界限，对 β=0.5 的选择只在两种消融环境做了经验说明——未系统扫描 β，无法确认 β=0.5 是否全局最优或接近最优。
8. **自适应性偏差/存活者偏差**：论文在结论中诚实承认对累积优化过程的许多臂估计不足可能造成偏差，并把“构建对自适应采样的无偏估计器”作为未来方向——这是一个真实、未解决的局限。
